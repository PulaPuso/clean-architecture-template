A complete, runnable Clean Architecture solution in one command.

A dotnet new template for enterprise applications on ASP.NET Core 10 and .NET Aspire. Pick Angular, React or Web API only; pick SQLite, PostgreSQL or SQL Server. You get a layered back end, an Aspire AppHost that runs everything locally, and unit, integration, functional and acceptance test projects already wired up. A starting point you own, not a framework you depend on.

dotnet new ca-sln -cf none -db sqlite -o YourProjectName

Start in four steps

Prerequisites: .NET 10 SDK. Node.js LTS only if you choose a SPA; Docker or Podman only if you choose PostgreSQL or SQL Server. SQLite, the default, needs no container.

1 · Install the template

dotnet new install CleanArchitecture.Template from NuGet, or dotnet new install ./ from a clone of the repo.

2 · Create a solution

dotnet new ca-sln --client-framework angular --database sqlite --output YourProjectName. Defaults are Angular and SQLite; --help lists every option.

3 · Run it

dotnet run --project .\src\AppHost. The Aspire dashboard opens with the application URLs, logs and traces.

4 · Test it

dotnet test. Functional and integration tests start their own database through Aspire's TestAppHost; acceptance tests run on Playwright.

What's inside

Dependencies point inward. The Domain has no dependencies; Application depends on Domain; Infrastructure and Web depend on Application; the AppHost composes the runnable pieces.

Domain

Entities, value objects, enums, domain events, exceptions. No external dependencies.

Application

Use cases as MediatR commands and queries, validators, DTOs, and pipeline behaviours for validation, authorisation, logging, performance tracking and unhandled exceptions on every request.

Infrastructure

EF Core DbContext and migrations, identity, external service implementations.

Web

ASP.NET Core minimal API endpoints, OpenAPI via Scalar, and the Angular 21 or React 19 client app.

AppHost & ServiceDefaults

.NET Aspire orchestration — database container, Web project, dashboard — plus shared health checks, OpenTelemetry and resilience defaults.

Tests

Domain and Application unit tests, Infrastructure integration tests, Application functional tests and Playwright acceptance tests. NUnit, Shouldly, Moq, Respawn.

Scaffolding and decisions

The solution ships with an item template for new use cases, and the reasoning behind the shape of the template is written down.

  1. ADR-001 — Use EF Core in the Application layer.
  2. ADR-002 — Aspire for orchestration and testing.
  3. ADR-003 — MediatR contracts in the Domain.

Run dotnet new ca-usecase from src/Application to add a command or query with its feature folder. To work on the template itself, .\build\repack.ps1 packs the nuspec, uninstalls the old version and installs the new one. GitHub Actions build the solution, run CodeQL, exercise every client and database combination, and publish the package on release.

# New command
dotnet new ca-usecase --name CreateTodoList --feature-name TodoLists --usecase-type command --return-type int

# New query
dotnet new ca-usecase -n GetTodos -fn TodoLists -ut query -rt TodosVm
